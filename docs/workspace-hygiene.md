# Workspace Hygiene

This repository is often inspected from a local working folder that may contain
many Rust build directories and prior test logs. Those files are useful during
debugging, but they add noise to code review and text search.

## Confirm The Current Directory

Run:

```powershell
Get-Location
Test-Path .git
git status --short
```

If `Test-Path .git` is `False`, the current folder is not a Git repository.
That does not change runtime behavior, but it means Git cannot show an
authoritative diff or rollback point for this folder.

## List Review Noise

Run:

```powershell
Get-ChildItem -Directory -Filter "target*"
Get-ChildItem -File -Filter "cargo-test-*.log"
```

These paths are generated build or validation artifacts:

- `target`
- `target-*`
- `cargo-test-*.log`

They can usually be regenerated by `cargo check`, `cargo test`, or commands
that set `CARGO_TARGET_DIR`.

## Do Not Delete Blindly

Do not delete:

- `src`
- `tests`
- `web`
- `docs`
- `config`
- `fixtures`
- `Cargo.toml`
- `Cargo.lock`
- `.env.example`
- `.runtime` unless you intentionally want to remove local runtime state

Before deleting generated artifacts, stop running Rust commands and make sure no
terminal is still compiling against the same target directory.

## Prefer Isolated Cargo Target Directories

For long or experimental validation runs, prefer:

```powershell
$env:CARGO_TARGET_DIR="target-local-check"
cargo test --test safety_tests
```

This keeps temporary build output separate from the default `target` directory.
Build-cache target directories are operational workspace artifacts, not product
logic changes.

## Git Recommendation

If this folder is meant to be the active source of truth, initialize or restore a
Git repository before broad edits. A Git repository makes it easier to review
changes, separate generated artifacts from source files, and recover from
accidental edits.

Use the companion script for a read-only snapshot:

```powershell
.\scripts\check-clean-workspace.ps1
```
