## 待办任务

### 1. SQLite WAL / 索引优化

- 优先级：P0
- 状态：已实现
- 范围：统一 WAL、`NORMAL` synchronous、checkpoint、`busy_timeout`、读写连接参数和评级/时间查询索引。
- 目标：降低写入锁等待、减少无效全表扫描，并让事件时间范围、评级筛选、生命周期关联查询使用稳定索引。
- 安全门槛：先做只读基线和外部备份；没有备份、磁盘不足或无法证明收益时，不执行 `VACUUM`、大批量 `DELETE` 或不可逆索引改造。
- 验收：本地 WAL profile、迁移、持久化与事件 API 测试通过；生产以健康检查和日志持续观察。

### 2. 历史事件冷热分层

- 优先级：P0
- 状态：已实现
- 范围：热表 + 普通冷归档表 + 永久表，统一历史视图和按保留窗口幂等归档。
- 目标：热库只保留实时监控和近期查询需要的数据；历史事件进入只读冷归档，查询按时间范围路由到热库或冷库。
- 安全门槛：先完成 schema、迁移批次、幂等键和回滚方案；归档校验未通过前，不删除热库原始数据。
- 验收：历史查询、时间线和事件统计统一读取历史视图；归档失败不会阻断实时写入。

### 3. A/S 永久库 + 普通事件归档库分离

- 优先级：P0
- 状态：已实现
- 范围：基于持久化 V3 评级，将确认 A/S 事件写入永久库，B 按延长窗口保留，普通事件写入冷归档库。
- 目标：永久库保留评级版本、证据、理由、来源和审计链；普通事件按保留策略归档，避免永久库无限增长。
- 安全门槛：永久资格只能由持久化 V3 评级决定；评级缺失或版本不兼容时降级为普通归档，禁止凭旧 severity 字段永久保留。
- 验收：A/S 记录带评级版本、状态、理由和证据审计字段；普通事件按策略分层；历史 API 统一读取；本地相关测试通过。

### 4. 运行快照增长控制

- 状态：已实现，生产积压清理待观察
- 运行快照（`flow_snapshots`、`toxic_snapshots`、`venue_health_snapshots`）按 24 小时窗口保留；VPIN 桶保留 14 天，事件保留 30 天。
- 清理任务每 15 分钟运行一次；正常模式按批次和单表时间预算删除，数据库达到约 70GiB 或磁盘达到 80% 后自动进入 burst 模式。
- burst 模式提高批量、取消批间等待并扩大单表预算；磁盘达到 84% 或剩余空间低于 24GiB 时进入 emergency burst。
- 磁盘达到 88% 时启用 snapshot 写入保护，优先保证评级、API 和实时采集进程可用。
- 不使用 `VACUUM` 作为日常清理；删除后的空闲页由 SQLite/WAL 后续写入复用，物理压缩另行安排维护窗口。
- 观测重点：`runtime retention policy selected`、`runtime retention prune completed`、`time_budget_reached`、`batch_limit_reached`，以及 `/healthz`、`/readyz`。

## 统一安全约束

- 不把业务数据库、`.env`、密钥或 Docker 运行卷当作缓存清理。
- 所有删除前必须有外部备份或 VPS 快照。
- 迁移必须幂等、可观测、可暂停、可回滚。
- 归档或数据库维护失败不得影响实时评级、API 可用性或 Discord 安全门。
